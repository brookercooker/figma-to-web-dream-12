# Site Manager (src/pages/admin) rules

- Top-bar Objects/Images/Videos use LibraryPicker on Preview in Chat Mode, EditorSlot.requestAdd in page Manual Edit Mode (append beneath original, no add row), and navigate on management tabs. All pickers share TopDropContent: measured opener/toolbar/area bounds, right-edge flip/clamp, resize observation, connector, pressed opener and focus return keep panels attached without layout shift. LibraryPicker deduplicates attached refs, shows at most eight label chips plus a counted searchable folder menu, and sends DesignChatContext refs as plain text appended to the message; /send never changes.
- Objects open in the same DesignTab/FramedPageEditor at `/__object/<id>?nova-edit=1` (`?editObject=` on /manage/preview; /manage/objects/design redirects unless `legacy=1`); edit-init/update send `scope:"object"` + `object` snapshot (+ `edits` override), frames must announce `capabilities.objectEditing`, every object edits under `object:<id>`, `edit-error` shows Retry. Designed objects = not a registered coded component (component_key may remain); their sections are the held blocks (no page marker) saved to object_registry.content, with per-section Section Layout. The standalone designer stays only for objectSectionsEdit LAYOUT_GAPS and new-object creation.
- Object clicks open the editor directly when the object is used only on this page (or is a page-only copy); otherwise ask Edit Everywhere / Make a Copy / Cancel; Header/Footer keep the site-wide dialog.
- Editor saves go through saveRow, which treats an update that returns no row as a failure (RLS skips are silent); paths starting with `/__`, /manage, /admin or /preview are never registered as pages (isInternalPath).
- Object status is a deprecated compatibility field, never an availability gate; creation defaults and frame snapshots remain compatible with older consumers while archive checks determine availability.
- sectionList-capable frames supply bounded, trusted edit-sections snapshots; row selection sends scroll-to-section, held mutations use Manager state and coded section commands must return edit-change for persistence. Older frames retain the local list; snapshots never enter stored content.
- Unsaved counts use merged undo steps (minimum one for staged resets); reset actions are staged until Save Changes, page reset never clears shared-object overrides, and object reset only clears its object:<id> map.
