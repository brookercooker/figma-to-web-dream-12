# Site Manager (src/pages/admin) rules

- Top-bar Objects/Images/Videos use LibraryPicker on Preview in Chat Mode, EditorSlot.requestAdd in page Manual Edit Mode (append beneath original, no add row), and navigate on management tabs. All pickers share TopDropContent: measured opener/toolbar/area bounds, right-edge flip/clamp, resize observation, connector, pressed opener and focus return keep panels attached without layout shift. LibraryPicker deduplicates attached refs, shows at most eight label chips plus a counted searchable folder menu, and sends DesignChatContext refs as plain text appended to the message; /send never changes.
- Objects open in the same DesignTab/FramedPageEditor at `/__object/<id>?nova-edit=1` (`?editObject=` on /manage/preview; /manage/objects/design redirects unless `legacy=1`); edit-init/update send `scope:"object"` + `object` snapshot (+ `edits` override), frames must announce `capabilities.objectEditing`, every object edits under `object:<id>`, `edit-error` shows Retry. Designed objects = not a registered coded component (component_key may remain); their sections are the held blocks (no page marker) saved to object_registry.content, with per-section Section Layout. The standalone designer stays only for objectSectionsEdit LAYOUT_GAPS and new-object creation.
- Object clicks open the editor directly when the object is used only on this page (or is a page-only copy); otherwise ask Edit Everywhere / Make a Copy / Cancel; Header/Footer keep the site-wide dialog.
- Editor saves go through saveRow, which treats an update that returns no row as a failure (RLS skips are silent); paths starting with `/__`, /manage, /admin or /preview are never registered as pages (isInternalPath).
- Object status is a deprecated compatibility field, never an availability gate; creation defaults and frame snapshots remain compatible with older consumers while archive checks determine availability.
- sectionList-capable frames supply bounded, trusted edit-sections snapshots; row selection sends scroll-to-section, held mutations use Manager state and coded section commands must return edit-change for persistence. Older frames retain the local list; snapshots never enter stored content.
- Reset actions are staged until Save Changes, page reset never clears shared-object overrides, and object reset only clears its object:<id> map.
- rangeFormatting-capable frames report validated edit-range for the current selected key/scope; inert selections carry marks and guarded edit-format senders. Formatting remains frame-owned and resulting edit-change enters the existing Manager save/history pipeline, avoiding cross-frame DOM ranges or a second persistence path. Selection descriptions accept legacy string and structured section/role context and prefer frame plain text over flattened HTML; range updates never deselect. Computed colours/font stacks are display metadata, not restricted to palette/menu values.
- SelectedWording patches sanitized text nodes with fast-diff and writes the existing HTML inline key; unchanged formatting survives and normal edit-update/save/history remain authoritative, without a separate text storage path.
- Page picture removal emits hidden:<path>="1"; form hints emit placeholder:<path> strings sliced to 300 characters, clearing removes the override. Public 89e55b8's verbatim core validates both kinds, so incoming mixed maps remain intact; validation is not proof of DOM replay. Material icons use the trusted iconMarkup adapter, never pasted HTML.
- Collapsed rail expansion is tied to dropdown onOpenChange (not click alone, since Radix opens on pointerdown); Review expands before toggling so actions are visible.
- Link-address choices are non-submitting buttons that preserve mouse focus and only write link overrides, never Manager navigation; field pointerdown/focus/click each open the chooser. Material help uses explicit hover/focus state in a portalled tooltip above editing layers so pointer-origin focus cannot suppress keyboard help.
- Resolve colour tokens to concrete hex before edit-format; public frames do not inherit Manager CSS variables. Position stores px letter spacing and unitless line height. Frame object placements are trusted session metadata merged with manifest/saved usage, never page content. Held section rows update optimistically from Manager history, and equal frame payloads are not resent to avoid redundant public replays.
- Preview snapshots refresh on every trusted preview-ready, iframe load and mode/page transition, logging counts and reason only; this keeps a retained Chat iframe current without reloads or listener recreation.
- Chat and Manual frames share the public-preview base; only retain embed credentials when its origin matches the configured public site, never render Manager-local pages in Chat, and compose page paths by replacement rather than appending to an embed route.
- Library image references use stored delivery URLs in web/fallback/original order, never storage URLs synthesized from web_path; thumbnail fallbacks share the same candidates while signed/local previews retain priority.
- Manager owns document.title while mounted so visitor thumbnail effects cannot change it; page tables use container-aware secondary-column hiding and fixed right actions to preserve names/status/actions in the available pane.
- Trusted edit-key Delete/Backspace invokes the same reversible hidden edit as Delete Image only for the current image selection; footer selections use the site-wide object confirmation.
- Narrow screens use useManagerLayout tiers: phone Chat is a retained pop-out sheet with presentation-only attention signals; Manual keeps its Page/Sections tabs and edit sheet. Tablet/laptop keep the remembered resizable panel and wide is unchanged. Hide, never unmount chat/preview to retain drafts and scroll. Desktop uses ScaledViewport at 1280 px; navigation stays in the toolbar.
- Phone drawing finishes without clearing marks and notifies the retained chat sheet; sending continues through the existing prepare/send path so drawing attachments retain their original protocol.
- Phone attention baselines the first loaded relay history; only later timestamps or new approval/review transitions can alert. Chat and Manual use the selected virtual device width in ScaledViewport without remounting the editor.
- Successful public page/object lifecycle, metadata and redirect mutations use the existing contentSync queue with named notes; deferred deletion notifies after commit, keeping packages current without a second queue.
- Chat draft text and selection live in DesignChatProvider above the stable composer; updates cannot erase typing/focus, and completed sends clear only their unchanged submitted draft.
- The picked working-page descriptor is validated and restored from guarded tab sessionStorage into both the chip and initial preview path (not editing state); deliberate picks replace it and initial navigation is pinned so stale home reports cannot win after reload.
- PreviewToolbar uses reported locations and the shared page loader; Chat picks use selectPage and Manual picks use the existing unsaved guard. Reload reuses Chat retry or remounts only FramedPageEditor via a local event, preserving Manager-held edits and replaying edit-init rather than writing or changing loading protocols.
- Preview navigation confirmation, history and remembered-path pins share previewHistory normalization of home aliases, trailing slashes and equivalent queries, and strip `__lovable_*` preview credentials before comparing, storing or remembering, to avoid false fallback reloads and token reuse. Back/Forward send non-sticky in-place "to" for the Manager-history address, because reloaded preview frames have no browser history of their own. Keep the three-second fallback; guarded sessionStorage nova:debug-nav=1 enables navigation diagnostics without embed URLs.
- TextIconLinkPanel reuses scoped icon/link/position overrides and Manager history/save; all placement validation now goes through the verbatim shared core, avoiding divergent extension acceptance. Material name-only UI normalizes case before the existing parser; color drafts remain local to the picker until Apply so cancellation never records history or crosses the frame.
- Collapsible text expansion uses trusted selection.expandable metadata and capability-gated edit-expand requests; refreshed edit-select confirms state without content/history writes, keeping public interaction and DOM ownership in the frame. Icon previews use selected computed/overridden text size rather than picker glyph size.
- AdminShell owns one useSaveProgress view and passes it unchanged to the chat save-status line; content jobs never render the independent relay working line, preventing save-feedback dismissal drift. Manual Edit saves have no success toast; errors retain existing reporting.
- Chat StageRibbon lives above the retained interactive PreviewPanel and decorates existing timedProgress fill/wording; session-persisted job-ID runs show oldest unfinished first, match draft.requests/changes SHA by exact ID (timestamps only for older relays), prefer per-change builtAt and preserve separate build/frame baselines. Preview rebuilds never dim or cover the retained frame; Submit/save retain WaitProgress and estimates.
- useChangeQueue owns tab-session FIFO prepared send payloads in retained ChatPanel; assistant timestamps release one request without waiting for preview, new job/user baseline gates the next release, and uncertain in-flight reloads require explicit retry to avoid duplicate sends. Page-chip changes clear queued context; relay errors/approvals never automatically release requests.
- SavedVideoOptions and Sections operate only on held page/object content through changeBlocks/history and Save; nested object videos retain sibling content. Manager previews are posters, never players; saved-content reply handoffs use one-shot page-scoped selection hints and the existing mode guard, with no new relay messages.
- MediaAlignment shares joined alignment controls across saved media; Video Layout uses existing page percentage width versus object-video pixel width and containing-section alignment, preserving the public content schema.
- waitSuggestions ranks only available existing actions from saved page/draft/device/request context; ChatPanel loads optional context once per page wait and rotates per-wait session sets without altering the send queue or ribbon.
