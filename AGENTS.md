
- Coded pages are edited in place via InlineEditSurface; page overrides live in pages.inline_edits, shared-object overrides in object_registry.inline_edits (objects found via React fiber walk in lib/objectScopes), both keyed by DOM position and re-applied site-wide by InlineEditsLayer — avoids lossy conversion and keeps objects consistent everywhere.
- Coded objects open as live, as-built parts (locked sections with codedKey+chunk rendered by CodedChunk); only parts the user edits are converted, in place within the whole object — keeps untouched parts pixel-identical.
- Editor canvases share useEditorLinkGuard; visitor actions dispatch selection explicitly before propagation is blocked, keeping navigation disabled without disabling editor controls.
- Site Manager reads/writes the real Lovable Cloud database via `src/prototype/client.ts` (product catalog still demo); open-access `dev_open_all` policies are temporary while building and must be dropped before launch.
- Page additions share pure insertion helpers; media pickers remember positions and create filled blocks only on selection, so cancellation cannot dirty the page.
- Manual editing registers visitor pages through a deduplicated path cache; empty-content embedded pages resolve live components from the public-site manifest, so new public routes do not require editor allowlist updates.
- Manifest synchronization and edit policy share the draft-first manifest loader; sync batches missing paths once per build and relies on a unique pages.path index to prevent cross-tab duplicates without changing existing records.
- Capture uses an isolated camera sheet with session-scoped stream cleanup and passes JPEG Files into existing staging; uploads stay unchanged and camera failure uses a single-photo native input.
- LivePreviewPage resolves a page to found | missing | unreachable (never a silent DbPage fallback); DesignTab gives missing+empty pages unsaved starter blocks and unreachable pages a Retry panel, so failed code loads can never be overwritten.
- The draft-manifest reachable flag is stored with each cached manifest load; resolveLivePage only returns "missing" when the draft list (or, with no draft, the public list) was actually read, otherwise "unreachable".
- "/" and "/home" are one page: lookups, caches and registration go through registerPage homeAliases/pageKey, and the front page is only ever stored as "/".
- Top-bar Objects/Images/Videos open LibraryPicker (except while editing by hand) using the pickers' exported loaders; picked items live in DesignChatContext refs and are sent as a plain-text block appended to the message, so the /send format never changes.
